# MongoDB 迁移规范

数据库结构变化通过 `backend/app/migrations.py` 中的顺序迁移执行。每个迁移拥有不可变整数版本和名称，成功后写入 `schema_migrations`。迁移必须可重复运行，避免依赖某次部署的内存状态。

新增迁移时不得修改已经发布的迁移函数。涉及大量数据的迁移应采用分批游标并在部署说明中标注预计时间、磁盘需求和恢复方式。应用启动前应完成 MongoDB 与 MinIO 备份。

## v2.1.0 升级兼容

图片用途保存在数据集当前成员与版本成员中，旧记录缺少字段时按“未划分”读取，不批量改写旧版本。已存在的一对多标注关系保留，新建关系执行一份标注最多对应一张图片的约束；受影响的部分导出可能返回冲突。发布接口新增质量检查令牌，模型参数保存新增修订号，旧客户端须同步更新。升级前备份数据库、对象存储和部署配置。

## v2.2.0 升级兼容

迁移 006 为已有模型格式增加 `.caffemodel`、`.solverstate`、`.mdl`，将模型框架的三个旧预置值替换为新默认值，同时保留其他自定义值；启动初始化补齐“数据来源”标签。旧数据集缺少 `classification_rule` 时按标准规则读取。切换规则只重置当前图片分类和自定义分类定义，不修改已发布版本。升级前备份 MongoDB、MinIO 和部署配置；回滚应用镜像不会回滚已执行的迁移或用户数据。

## v2.0.0 升级兼容

本版不增加必须手工执行的迁移。启动初始化使用仅插入时设置的方式补齐六类 16 项预置指标，不覆盖已有定义；模型尚无 `metric_values` 时按未配置处理。

旧数据集缺少 `projects` 仍可读取，但编辑和复制要求先补齐有效项目。不要批量猜测或自动填入项目标签。删除关联素材会移除当前与历史版本成员并更新统计；此行为不是迁移，也不能通过降级镜像撤销。升级前保留数据备份，恢复需同时考虑元数据、对象文件与部署配置。
