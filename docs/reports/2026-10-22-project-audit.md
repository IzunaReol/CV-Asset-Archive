## 优先修复项

### 1. 素材详情切换发生旧响应覆盖（高优先级，已复现）

复现：打开 first.txt 并延迟详情响应，切换到 second.txt，待第二项显示完成后释放第一项响应。页面标题从 second.txt 变回 first.txt。

原因：frontend/src/App.vue 的 openAsset（约第 533 行）在请求返回后直接写入 detailAsset、remarkDraft 和操作历史，没有检查请求是否仍属于当前素材。关闭详情时同样没有使请求失效。

影响：连续切换时可能显示错误的素材详情、备注或历史，增加误操作风险。此次只验证了显示被覆盖，没有执行备注保存或删除。

建议：使用请求序号或取消请求机制；更新详情、历史、标注前统一检查当前素材 ID；切换和关闭时使旧请求失效。补充响应乱序及关闭后返回的回归用例。

### 2. 长项目名单选时撑宽手机页面（中优先级，已复现）

复现：项目名称为连续 100 个英文字母，单选该项目。1440 px 桌面正常；390 px 视口下页面 scrollWidth 为 986 px。

位置：frontend/src/views/ProjectOverviewView.vue 的 project-picker-trigger 文案和样式（约第 61、119 行）。项目名称允许的长度可以触发此问题。

建议：给名称独立容器，设置 min-width:0、最大宽度与省略号，保留完整名称提示；同时检查下拉选项内长文本换行。

### 3. 开发测试依赖出现漏洞提示（优先升级）

npm audit 当前结果：Vite 为 1 项高危受影响依赖；Vitest、@vitest/mocker、@vitest/coverage-v8 为 3 项中危受影响依赖。生产依赖审计为 0 项。

审计建议 Vite 升级到 7.3.7，Vitest 相关受影响范围低于 5.0.3。应协调升级 Vitest 和覆盖率插件，复跑构建与测试。

参考审计返回的公告：

- https://github.com/advisories/GHSA-587h-7wmj-h5pm
- https://github.com/advisories/GHSA-qxg6-89mg-rqv8
- https://github.com/advisories/GHSA-xp26-3454-mjgp

Docker 最终前端阶段为 Nginx 加 dist 静态文件，不运行 Vite/Vitest 服务；上述告警主要针对开发测试工具链，不能据此断言当前生产容器可被利用。

### 4. 隔离 API 全流程脚本已与接口契约脱节（中优先级，已验证）

scripts/runtime-e2e.py 第 122 行仅传 name 创建数据集，而 DatasetCreate 的 projects 已为必填。以当前模型校验脚本请求，确认缺少 projects 字段。

建议：在隔离环境准备项目标签，创建数据集时传入有效 projects；然后运行真实上传、后台处理、成员加入、版本发布、模型关联与清理全流程。本轮未把旧脚本标为通过，也未对业务库执行它。

## 其他代码检查发现

1. **操作历史“展示全部”仍只有最近 100 条。** backend/app/routers/assets.py 第 614 行固定 limit(100)，接口没有总数或后续分页；前端只展开已返回数组。当前真实数据没有任何素材历史超过 100 条，属于尚未触发的容量边界。建议分页/继续加载，明确总数。
2. **添加模型关联的选择列表仅加载前 200 个模型。** frontend/src/DatasetView.vue 第 161 行固定请求第一页、200 条，没有后续加载入口。当前只有 4 个模型，暂未影响实际使用。建议服务端搜索与分页选择。
3. **模型时间字段读写不一致。** 参数保存更新 modified_at，而数据集模型列表读取 updated_at。代码存在显示时间未随参数保存变化的风险；本轮现有 4 个模型未发现 modified_at 晚于 updated_at，未执行真实修改验证。建议统一语义并补保存后的时间展示测试。
4. **项目概览查询随项目数增长。** 每个项目分别查询文件数量、类型聚合、文件列表。当前 3 个项目查询正常；更多项目和素材时应合并聚合查询，并测试分页和响应大小。
5. **测试覆盖范围需要更准确。** 前端覆盖率配置仅包含选定工具与 composable；后端 system 为 23%、datasets 为 48%。应优先补异步乱序、参数保存联动、真实接口返回格式和权限组合，而不是只增加正常路径断言。
