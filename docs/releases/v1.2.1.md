# v1.2.1

v1.2.1 主要改进大文件上传、批量操作和部署维护能力，不改变现有数据集与模型关系结构。

## 更新内容

- 64 MB 及以上文件使用 64 MB 分片上传。重新选择同一文件时，可复用未过期会话并跳过已完成分片。
- 素材库“全部”使用服务端选择集。批量标签、删除、集合创建和导出支持排除个别素材，不再依赖前端保存全部素材 ID。
- 多文件上传合并初始化和完成请求，并提高小文件并发数量。
- 数据集写入锁增加到期续租；中断的版本恢复可在下一次写入前继续完成。
- 导出接口只接受素材 ID 或服务端选择集，不再接受原始数据库查询对象。
- 增加 Docker Compose 备份恢复脚本和隔离数据库的合成素材性能测试脚本。
- CI 增加 Python 依赖审计、容器镜像扫描和仓库密钥扫描。
- Docker Compose 支持分别配置浏览器访问 MinIO 的地址与 HTTPS，并统一 API 和 Worker 的 MinIO 凭据。
- 前端运行镜像使用持续维护的 Nginx Alpine 稳定版，并在构建时更新系统安全补丁。

## 从 v1.2.0 升级

升级前备份 MongoDB、MinIO 和部署配置。更新代码与依赖，重新构建前端和容器，然后检查登录、上传、批量选择、数据集写入、导出和回收站。

分片上传会创建临时对象，成功合并或取消会话后会清理。浏览器从其他电脑访问时，需要把 `MINIO_PUBLIC_ENDPOINT` 设置为浏览器可访问的地址；使用 HTTPS 时同时设置 `MINIO_PUBLIC_SECURE=true`。

## 验证情况

本地已通过 65 项后端测试、Ruff 检查、前端类型检查和生产构建。新增测试覆盖分片上传契约、批量上传、服务端选择集、数据集写入恢复和备份脚本的安全检查。

## 已知限制

- 尚未使用接近 10 GB 的真实文件完成上传验收。
- 10 万条元数据性能脚本已经提供，发布环境的性能基线仍需实测。
- Docker Compose 备份恢复脚本尚未在全新 Linux 主机完成实机演练。
- 前端尚未提供暂停按钮；刷新或中断后需要重新选择同一文件才能继续上传。
- CVAT 在线任务同步和 MLflow 集成尚未实现。
