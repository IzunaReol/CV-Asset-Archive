# v1.2.0

v1.2.0 调整了数据集、标注和模型之间的关联方式，并更新了模型溯源页面。

## 更新内容

- 模型改为关联已发布的数据集版本。模型溯源从版本成员展示图片、标注、视频和压缩文件，不再建立模型与单个素材的直接关系。
- 图片加入数据集时，已关联的标注会一同加入。移除图片或解除图片与标注的关系时，当前数据集中不再被其他图片使用的标注会随之移除；已发布版本不受影响。
- 模型关系图显示未标注图片及其他素材类型，支持按类型筛选，并标明素材所属的数据集和版本。
- 调整数据集的素材选择、筛选和分页；提高多文件上传时的小文件并发数，显示处理进度。
- YOLO 标注缺少类别名称时，预览显示“未命名类别”，不再显示数字 ID。

## 从 v1.1.0 升级

升级前备份 MongoDB、MinIO 和部署配置。旧的模型与素材直连关系不会自动转换为模型与数据集版本的关系。

在 `backend` 目录运行 `python -m scripts.cleanup_model_asset_relations`，先查看旧关系报告。确认清理范围后，使用 `--apply --confirm-count <报告数量> --backup <仓库外的绝对路径>` 备份并清理旧直连关系。审计记录保留。清理完成后再次运行报告，确认数量为零。

更新依赖和服务后，在 `frontend` 目录执行 `npm ci`、`npm run build`。启动 API、Worker 和前端，再检查登录、标注预览、数据集版本、模型溯源、导出及回收站。需要回退已清理的关系时，使用升级前的数据库备份；仅回退代码无法恢复这些记录。

## 验证情况

本地已通过 54 项后端测试、Ruff 检查、前端构建和隔离数据库接口测试。使用现有模型核对了关系图中的 159 张图片和 100 个标注文件，以及类型筛选和来源版本显示。

真实批量上传、10 GB 文件、10 万条元数据、Linux 全新部署、备份恢复和安全扫描尚未完成验证。详情见[发布检查单](../release-checklist.md)。

## 已知限制

- 上传尚不支持分片、暂停或断点续传。
- 素材“全部”选择仍由前端分批读取，大规模批量操作尚未完成性能验收。
- 进程强制退出或数据库持续故障后的数据集写入恢复仍需完善。
- CVAT 在线任务同步和 MLflow 集成尚未实现。
